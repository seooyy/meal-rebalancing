# 05. 주요 식재료 가격 변동 시나리오

> **담당 B · 부분 편입** ([08번 역할분담](08_2일_역할분담.md))
> **인증키 확보 완료.** 최대 병목이 사라져 2일 범위에 일부 들어온다.
> 2일 안에 하는 것: 수집기 작성 + 한식 품목 기준 단가 확보 + 시뮬레이터 연결.
> 2일 안에 안 하는 것: 서양음식 전체 커버리지(원본에 데이터가 없음), 상승·하락 시나리오 정밀화.
> **단계 1~4가 우선이다.** B가 시뮬레이터를 끝낸 뒤 남는 시간에만 손댄다.

원문 우선순위 5번. 단계 4 시뮬레이터의 변동비를 실제 가격 변동과 연결한다.

## 현재 상태

`data/일별 도,소매 가격정보 API명세 및 관련 코드 정보/` 에는 **API 명세와 코드표만 있고 실제 가격 데이터가 없다.** 인증키는 확보했으므로, 이 단계는 수집기 작성부터 시작한다.

| 항목 | 상태 |
| --- | --- |
| 서비스키 발급 | ✅ 완료 |
| API 명세·코드표 | ✅ 확보 |
| 실제 가격 데이터 | ❌ **미수집** |
| 수집기 코드 | ❌ 미작성 |

확보된 코드표 시트: `구분코드`, `부류코드`, `품목코드`, `품종코드`, `등급코드`, `시군구코드`, `시장코드`

API 명세 확인 사항:
- Method `GET`, `returnType` JSON/XML
- 페이징: `pageNo`, `numOfRows` (기본 10, **최대 1000**)
- 조회 조건: `cond[exmn_ymd::GTE]` / `cond[exmn_ymd::LTE]` (YYYYMMDD), `cond[se_cd::EQ]`(구분), `cond[ctgry_cd::EQ]`(부류), `cond[item_cd::EQ]`(품목), `cond[vrty_cd::EQ]`(품종), `cond[grd_cd::EQ]`(등급), `cond[sgg_cd::EQ]`(시군구), `cond[mrkt_cd::EQ]`(시장)
- `selectable`로 응답 컬럼 선택 가능
- `serviceKey` 인증키 — **발급 완료**. `.env`의 `PRICE_API_KEY`로 읽는다

구분코드: 01~09 (소매 / 중도매 / 친환경농산물 / 친환경농산물(신규) / 온라인 등)

## 작업 절차

### 5-1. 키 설정과 수집 범위 확정

- `.env.example`을 `.env`로 복사하고 발급받은 키를 넣는다. **`.env`는 `.gitignore`에 등록돼 있어 커밋되지 않는다.**
  ```powershell
  Copy-Item .env.example .env    # 그 다음 PRICE_API_KEY 값을 채운다
  ```
- 키를 코드에 직접 쓰지 않는다. 노트북 출력에도 찍히지 않게 주의한다.
- 수집 기간: **2026-01-01 ~ 2026-06-30** (카드 데이터와 동일 구간)
- 수집 대상 품목: 일반한식·서양음식 각 대표 메뉴 3개의 레시피에서 원가 비중 상위 품목만 선정 (전 품목 수집하지 않는다)

### 5-2. 품목 선정

메뉴별 레시피에서 원가 기여 상위 항목을 뽑는다. **업종별로 목록이 다르다.**

#### 일반한식 (커버리지 양호)

| 부류 | 품목 후보 |
| --- | --- |
| 식량작물 | 쌀 |
| 채소류 | 배추, 무, 파, 양파, 마늘, 고추 |
| 축산물 | 돼지고기, 쇠고기, 닭고기, 계란 |
| 수산물 | 고등어, 오징어 |

한식 원가의 대부분이 농축수산물이라 이 API로 충분히 커버된다.

#### 서양음식 (커버리지 부족 — 주의)

API의 부류코드는 **식량작물 / 채소류 / 특용작물 / 과일류 / 축산물 / 수산물** 6개다. 즉 **농축수산물만 제공된다.**

서양음식 원가의 핵심 항목 상당수가 여기에 없다.

| 원가 항목 | API 커버 | 대체 방안 |
| --- | --- | --- |
| 육류 (돼지·소·닭) | ✅ 축산물 | 그대로 사용 |
| 채소 (양파, 토마토, 마늘 등) | ✅ 채소류 | 그대로 사용 |
| **밀가루 / 파스타면** | ❌ | CPI 품목(단계 6) 또는 가정값 |
| **치즈 / 버터 / 우유** | ❌ | CPI 품목 또는 가정값 |
| **올리브유 / 소스류** | ❌ | CPI 품목 또는 가정값 |
| **수입육 / 가공육** | ❌ | 가정값 |

**대응 방침**: 서양음식 예시 매장의 원가는 "일부 품목만 공개 가격 기반, 나머지는 가정값"임을 화면에 명시한다. 커버리지 비율(원가 중 실측 가격이 적용된 비중)을 계산해 표시한다.

이 공백 때문에 **서양음식은 식재료 가격 시나리오의 정밀도가 한식보다 낮다.** 단계 7 인터뷰에서 서양음식 매장의 실제 매입단가 확보 우선순위를 높인다.

품목 최종 목록은 단계 4의 `config/demo_store_korean.yaml` / `config/demo_store_western.yaml` 레시피에서 역산해 확정한다.

### 5-3. 수집기 구현

- `src/collect_price.py` — 품목×기간 반복 호출, `numOfRows=1000`으로 페이징
- 호출 간 대기·재시도·실패 로그. 원시 응답을 `data/price_raw/` 에 날짜별로 보존
- 수집 후 `out/price_daily.csv`로 정규화

### 5-4. 일치 규칙 (필수)

`project_idea.md` 4절의 원칙이다. **품종·등급·단위·시장·도소매 구분이 일치하지 않으면 비교하지 않는다.**

- 구분(소매/중도매)을 섞지 않는다. 음식점 매입은 중도매에 가깝지만, 어느 쪽을 쓰는지 명시한다.
- 단위(kg, 개, 포기)를 레시피 사용량 단위로 환산하고 환산 계수를 기록한다.
- 시장·시군구는 매장 소재지 기준으로 고르되, 결측이면 전국 평균으로 대체하고 대체 사실을 표기한다.
- 등급이 여러 개면 하나를 고정하고 어느 등급인지 표시한다.

### 5-5. 시나리오 생성

```
시나리오 변동비 = Σ(품목 사용량 × 품목 단가 × (1 + 변동률))
```

| 시나리오 | 정의 |
| --- | --- |
| 기준 | 관측 기간 평균 단가 |
| 상승 | 관측 기간 내 상위 분위(예: 90퍼센타일) 단가 |
| 하락 | 하위 분위(예: 10퍼센타일) 단가 |
| 사용자 지정 | 특정 품목의 변동률 직접 입력 |

**주요 재료 가격 상승은 해당 재료를 쓰는 메뉴의 비용에만 적용한다.** 여러 메뉴가 영향을 받으면 단계 4의 매장 전체 공헌이익 비교로 넘긴다.

### 5-6. 실제 매입단가 우선

매장의 실제 매입단가가 있으면 **그 값을 기준으로** 변동 시나리오를 만든다. 매입단가가 없을 때만 공개 가격 기반 추정을 쓰고, 화면에 "공개 가격 기반 추정"을 표시한다.
