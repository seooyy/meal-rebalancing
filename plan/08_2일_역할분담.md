# 08. 2일 3인 역할 분담

3명이 2일(= 6인일) 동안 병렬로 진행하는 실행 계획이다. 시간 블록·담당자·산출 파일이 모두 지정되어 있다.

## 2일 안에 할 것과 안 할 것

| 단계 | 2일 범위 | 판단 |
| --- | --- | --- |
| 1. 데이터 정의·사례 집계 | ✅ 전부 | 나머지를 막는 기반 |
| 2. 지역·집단 진단 | ✅ 전부 | 핵심 화면 |
| 3. 유사 지역 비교 | ✅ 전부 | 인구 데이터가 이미 있음 |
| 4. 손익 시뮬레이터 | ✅ 전부 | 카드 데이터 의존 없음 |
| 5. 식재료 가격 | 🔶 **부분** | **인증키 확보 완료.** 수집기까지만. B의 여유 시간에 |
| 6. 물가·공급 | 🔶 **6-A만** | **CPI 확보·계산 완료.** C가 화면에 한 줄 붙이면 끝 |
| 7. 인터뷰·실험 | ❌ 제외 | 매장 섭외가 2일 안에 불가 |

**2일 목표 = 단계 1~4 완성.** 원문 12절의 "초기 완성 범위(지역 진단, 유사 지역 비교, 실행 후보, 손익 시뮬레이션)"와 정확히 일치한다.

**단계 5는 덤이다.** 인증키가 나와서 착수는 가능해졌지만, 단계 1~4를 밀어내면서까지 하지 않는다. B가 시뮬레이터를 끝내고 남는 시간에만 손댄다. 못 해도 2일 목표는 달성이다.

## 역할

| 담당 | 역할 | 맡는 단계 | 핵심 산출물 |
| --- | --- | --- | --- |
| **A** | 데이터 기반·진단 | 1 → 2 | `src/load.py`, `src/diagnose.py`, 집계 CSV |
| **B** | 손익 계산 | 4 (+5 여유 시) | `src/simulator.py`, 예시 매장 2종 |
| **C** | 지역 비교·화면 통합 | 3 → 화면 | `src/similar_region.py`, 화면 1·2 |

### 왜 이렇게 나누는가

- **B는 처음부터 끝까지 독립적이다.** 시뮬레이터는 판매가격·변동비·판매량만 있으면 계산된다. 카드 데이터를 기다릴 필요가 없다. 셋 중 가장 대기 시간이 적으므로, 진도가 빠르면 화면 작업을 C와 나눈다.
- **A는 가장 먼저 남을 막는다.** `src/load.py`가 없으면 C의 단계 3이 못 움직인다. 그래서 A의 1일차 오전 최우선 과제는 로더 하나다.
- **C는 1일차 오전에 카드 데이터가 필요 없다.** 인구 엑셀 파싱과 지역명 매칭이 먼저다. A의 로더가 나올 때쯤 카드 쪽으로 넘어간다.

## 2일 뒤 남는 것

원문 12절 기준 **1~4번 완료, 5번 부분, 6~7번 미착수**다. 발표·제출 시 "초기 완성 범위를 구현했고, 물가 보완과 매장 실험은 확장 계획"이라고 설명한다.

단계 5를 손댔다면 "실제 식재료 가격을 수집해 원가에 반영했다"를 추가로 말할 수 있다. 못 했더라도 인증키와 명세가 준비돼 있으므로 바로 이어갈 수 있다.
