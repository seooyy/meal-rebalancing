# 03. 인구 기반 유사 지역 비교

> **담당 C · 1일차 종일** ([08번 역할분담](08_2일_역할분담.md))
> 오전 인구 엑셀 파싱·지역명 매칭은 카드 데이터 없이 가능하다. 오후에 A의 로더로 넘어간다.
> **시작 전 `pip install openpyxl` 필요** — 현재 환경에 없어서 `.xlsx`를 못 읽는다.

원문 우선순위 3번. 진단 결과가 그 지역만의 현상인지, 비슷한 조건의 지역에서도 나타나는지 확인하는 기능이다.

## 목표

분석 시작 시점(2026년 1월)의 인구 규모·연령 구성·초기 소비 수준이 비슷한 시군구를 찾아, 대상 지역의 변화를 비교 맥락 안에 놓는다.

## 입력

- `data/202601_202606_연령별인구현황_월간.xlsx` (시트: `연령별인구현황`)
- `out/region_group_metrics.csv` (단계 2)
- `out/region_keys.csv`

## 작업 절차

### 3-1. 인구 데이터 정합

**반드시 `region_key`(= 시도 + 시군구)로 매칭한다. `CCG_NM` 단독으로 join하면 안 된다.**

시군구명은 233개인데 실제 지역은 255개다. 같은 이름이 여러 시도에 있다.

| 시군구명 | 존재하는 시도 수 |
| --- | --- |
| 중구, 동구 | 각 **6곳** |
| 서구 | 5곳 |
| 남구, 북구 | 각 4곳 |
| 강서구, 고성군 | 각 2곳 |

`CCG_NM`으로 인구 데이터를 붙이면 **22개 지역이 잘못 합쳐지고 에러도 나지 않는다.** 서울 중구 인구가 부산 중구에도 붙는 식이다.

```python
from src.load import load_card
d = load_card()          # region_key 열이 이미 들어 있다
d["region_key"]          # '서울특별시 중구'
```

인구 엑셀 쪽도 시도+시군구를 합친 키를 만들어 그걸로 join한다.

- 255개 **(시도, 시군구) 쌍**이 모두 매칭되어야 한다.
- 매칭 실패 건은 수작업 보정표 `config/region_alias.csv`로 관리한다. 통합시·자치구 개편 사례를 확인한다.
- 기준 시점은 **2026년 1월** 값으로 고정한다 (A기간 시작).

### 3-2. 매칭 변수

| 변수 | 출처 | 변환 |
| --- | --- | --- |
| 총인구 | 인구현황 | log 변환 |
| 20~30대 비율 | 인구현황 | 비율 |
| 60대 이상 비율 | 인구현황 | 비율 |
| A기간 일평균 결제금액 (**선택 업종**) | 카드 | log 변환 |
| A기간 건당 결제금액 (**선택 업종**) | 카드 | log 변환 |

**매칭은 업종별로 따로 수행한다.** 일반한식 진단을 보고 있으면 일반한식 기준으로, 서양음식 진단을 보고 있으면 서양음식 기준으로 유사 지역을 고른다. 한 지역이 한식에서는 A그룹, 서양음식에서는 B그룹에 속할 수 있고 그게 정상이다.

**결과 변수(B기간 변화율)는 매칭 변수에 넣지 않는다.** 넣으면 "비슷한 변화를 보인 지역"을 고르는 순환 논리가 된다.

### 3-3. 매칭 방법

각 변수를 표준화하고 유클리드 거리로 최근접 5개 시군구를 선정한다. 방법이 단순한 대신 다음을 반드시 표시한다.

- 선정된 유사 지역 5곳과 각 변수의 실제 값 (사용자가 납득 여부를 직접 판단)
- 대상 지역과의 거리
- 관측량 기준 미달 지역은 후보에서 제외

### 3-4. 비교 표시

| 항목 | 대상 지역 | 유사 지역 5곳 중앙값 | 전국 |
| --- | --- | --- | --- |
| 일평균 결제금액 변화 | | | |
| 일평균 결제건수 변화 | | | |
| 건당 결제금액 변화 | | | |
| 외국인 금액 변화 | | | |
| 법인 금액 변화 | | | |

대상 지역이 유사 지역 5곳의 범위 안인지 밖인지를 표시한다. 5개 표본의 중앙값이므로 통계적 유의성을 주장하지 않는다.

## 강남구 예외 처리 (필수)

강남구는 이 단계의 가정이 가장 크게 깨지는 지역이다.

강남구 서양음식 일평균 결제건수는 **48,792건**으로 미추홀구 서양음식(5,721건)의 8.5배다. 강남구 인구가 미추홀구의 8.5배가 아니므로, 이 격차는 주민 소비로 설명되지 않는다. 업무지구 유입과 가맹점 소재지 기준 집계의 결과로 보는 편이 타당하다.

따라서:

- 강남구에는 **"인구 구성이 비슷한 지역이라도 상권 성격이 다를 수 있습니다"** 경고를 고정 노출한다.
- 매칭 변수에 A기간 결제금액(log)이 들어 있어 어느 정도는 규모가 반영되지만, 인구 변수와 소비 변수가 충돌하는 지역에서는 거리 값이 커진다. **최근접 5곳의 거리가 전국 분포의 상위 10%보다 크면 "유사 지역 없음"으로 표시하고 비교표를 숨긴다.**
- 종로구·중구 등 유사한 유입형 상권도 같은 처리를 받는다. 지역명을 하드코딩하지 말고 거리 기준으로 판정한다.

## 금지 사항

- **지역 카드 소비를 주민 수로 나눠 "주민 1인당 외식비"로 제시하지 않는다.** `CCG_NM`이 가맹점 소재지인지 고객 거주지인지 확인되지 않았으므로, 관광·업무 유입 지역에서 이 값은 의미가 왜곡된다. 강남구 서양음식이 그 대표 사례다. 1인당 환산 함수를 코드베이스에 만들지 않는다.
- 유사 지역과의 차이를 매장 운영 문제의 근거로 제시하지 않는다.
- 업종이 다른 지역끼리 비교하지 않는다.

## 검증 기준

- [ ] 255개 **(시도, 시군구) 쌍**이 모두 인구 데이터와 매칭된다 (미매칭 0건)
- [ ] `CCG_NM` 단독 join을 쓰지 않았다 (중구·동구 등 22개 지역 오합산 방지)
- [ ] 인구 합계가 공식 발표 총인구와 오차 범위 내에서 일치한다
- [ ] 매칭 변수에 B기간 결과 변수가 포함되지 않았다
- [ ] 미추홀구의 유사 지역 5곳을 사람이 보고 납득 가능하다 (인구 규모·구성 육안 확인)
- [ ] 업종별로 매칭이 따로 수행되고, 같은 지역이라도 업종에 따라 결과가 다를 수 있다
- [ ] 강남구에서 거리 기준 판정이 작동한다 ("유사 지역 없음" 또는 경고 노출)
- [ ] 1인당 소비 환산이 코드·화면 어디에도 없다
